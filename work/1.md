# 1 — chore: finalize project bootstrap (install deps, CI green)

## 2026-05-10 — Initial development

### Summary
Finalisation du bootstrap Phase 1. `pnpm install` génère désormais le lockfile, et `pnpm lint`/`pnpm type-check`/`pnpm build`/`pnpm test` passent tous sur le scaffold actuel. La CI peut tourner au vert sur cette PR.

### Key decisions
- **`lightningcss` ajouté en devDependency** : `astro.config.mjs` configure `vite.css.transformer = 'lightningcss'`, mais le paquet n'était pas installé → build cassé. Ajout en dépendance plutôt que retrait du transformer (lightningcss est le choix arbitré dans `docs/03-tech-stack.md`).
- **`playwright test --pass-with-no-tests`** : les répertoires `tests/playwright/` et `tests/a11y/` sont vides (les tests sont des tickets dédiés Phase 1). Le flag rend `pnpm test` no-op tant qu'aucun test n'est écrit, sans crasher la CI. Le flag devient un no-op dès qu'un test existe.
- **Biome override pour `*.astro` étendu** : `noUnusedImports: "off"` dans l'override Astro, en plus de `noUnusedVariables`. Biome n'analyse pas le corps des templates `.astro`, donc il flaggait à tort `import DocLayout from '...'` et `import { ClientRouter }` comme inutilisés. `pnpm lint:fix` les supprimait → type-check cassé. Désactiver la règle pour `.astro` est la convention recommandée jusqu'à ce que Biome supporte mieux Astro.
- **`playwright.config.ts` — workers** : `workers: process.env.CI ? 1 : undefined` violait `exactOptionalPropertyTypes` (workers attend `string | number`, pas `undefined`). Remplacé par un spread conditionnel `...(process.env.CI ? { workers: 1 } : {})`.
- **`.worktrees/` ignoré** : le workflow `/develop` utilise des worktrees git (cf. `.worktrees/1-bootstrap`). On gitignore le dossier pour ne pas polluer les commits.
- **README — playwright install + simple-git-hooks** : documenté `pnpm exec playwright install --with-deps chromium` (one-shot) et précisé que `pnpm install` enregistre le hook `pre-commit` via `simple-git-hooks`.
- **Reformatages Biome** : `pnpm lint:fix` a aussi appliqué le style projet (lineWidth 100, quoteStyle single, organizeImports) sur `astro.config.mjs`, `src/stores/*.ts`, `src/styles/*.css`. Conservé tel quel — c'est précisément ce que `pnpm lint` exigerait à toute future PR.

### Difficulties
- `simple-git-hooks` postinstall échoue dans un worktree git (`ENOTDIR`, `.git` est un fichier pointeur, pas un dossier). Sans impact en CI ni en checkout standard. Documenté dans le README pour que le contributeur lance `pnpm install` dans le checkout principal.
- Le scaffold initial n'était pas compatible avec ses propres règles Biome — chaque ajustement (ajout du transformer lightningcss, types stricts pour exactOptionalPropertyTypes) avait son petit piège à corriger avant de commit.

### Diff size
~93 lignes utiles + lockfile généré. Single commit, pas de split nécessaire.

## 2026-05-10 — Code review notes

### Verdict
**Request Changes** (1 blocking, 1 important, 1 nit). Code et architecture cohérents avec le scaffold ; le ticket bute sur un seul point qui sort du périmètre développé mais qui appartient à ce ticket (« CI au vert »).

### 🔴 Blocking
- **CI échoue à `pnpm/action-setup@v4`** : le scaffold initial pinnait pnpm dans deux endroits :
  - `version: 9` dans les trois jobs de `.github/workflows/ci.yml`
  - `packageManager: pnpm@9.15.0` dans `package.json`
  L'action `pnpm/action-setup@v4` rejette ce double pinning (`Multiple versions of pnpm specified`). C'est le critère « CI GitHub Actions au vert sur cette PR » qui tombe.
  **Fix attendu** : retirer le bloc `with: version: 9` des trois jobs (la convention idiomatique est de laisser corepack/`packageManager` piloter). Modification dans la même PR.

### 🟡 Important
- **`--pass-with-no-tests`** est une mesure de transition. Quand le premier ticket Playwright (`recruiter.spec.ts` ou autre) atterrira, retirer le flag — sinon un mauvais `testDir` ou une regex foireuse passerait silencieusement en CI. À documenter explicitement comme TODO dans le ticket des tests Phase 1, sinon ce sera oublié.

### 🟢 Nits
- `playwright.config.ts` — le spread conditionnel marche, mais `...(process.env.CI ? { workers: 1 } : {})` se lit moyennement. Une alternative `workers: process.env.CI ? 1 : undefined as never` ou simplement `workers: process.env.CI ? 1 : 4` (chiffre fixe en local) serait plus directe. Pas bloquant.
