# 9 — feat(system): InspectPanel React island wired to selected-item store

## 2026-05-20 — Initial development

### Summary

Implements the Inspect panel (right column of `DocLayout`), the heart of the
Dev-Mode-Figma metaphor. The panel reads the `selectedItem` nanostore and
re-renders three sections — **Properties**, **Tokens**, **Used In** — whenever
a selectable element on the page mutates the store. To prove the wiring
end-to-end, the existing `ExperienceCard` is wrapped in a new
`SelectableExperienceCard` React island that publishes the experience's
properties / tokens / used-in to the store on click or Enter/Space.

Figma reference: frame `25:2` (InspectPanel component) in file
`Xw8ocCGiqdKjKK4lrDT0il` — pulled via the figma-pull skill before
implementation, per the user's standing workflow rule.

### Files

- `src/stores/selected-item.ts` — extended from minimal `{kind, id}` to a
  `SelectionData` shape carrying the three sections (`properties`, `tokens`,
  `usedIn`). The store itself is the source of truth for what the panel
  renders, which keeps `InspectPanel` a pure presentation component.
- `src/components/system/InspectPanel.tsx` — React island. Empty state when
  store is null, populated otherwise. `<aside data-state>` exposed for tests.
- `src/components/system/InspectPanel.css` — fits the column width given by
  `DocLayout`. Section headers use `--text-secondary`, mono key/value rows,
  token chips bound to CSS variables (no hex literals). Adds
  `view-transition-name: inspect`.
- `src/components/system/InspectPanel.stories.tsx` — 3 stories (Empty,
  ExperienceSelected, Dark) using a `withSelection()` decorator that seeds
  the store on mount and clears it on unmount.
- `src/components/cv/SelectableExperienceCard.tsx` (+ CSS) — interactive
  wrapper around `ExperienceCard`. `role="button"` + `tabIndex=0` so it's
  keyboard-reachable; Enter/Space activates. Adds a `data-hydrated` marker
  flipped on after `useEffect` so Playwright can wait out the `client:idle`
  race on mobile-safari.
- `src/patterns/ExperiencePreview.astro` — new `selectable?: boolean` prop.
  When true, the 2x2 grid renders `SelectableExperienceCard client:idle` per
  variant instead of the plain server-rendered card.
- `src/pages/components/experience.astro` — flips `selectable` on so the
  Preview tab actually wires up the inspect flow.
- `src/layouts/DocLayout.astro` — renders `<InspectPanel client:visible />`
  as the default fallback for `<slot name="inspect">`, so every doc page now
  has a working panel out of the box.
- `biome.json` — file-level override disabling `a11y/useSemanticElements`
  for `SelectableExperienceCard.tsx` (see "Difficulties" below).
- `tests/playwright/inspect-panel.spec.ts` — 4 Playwright specs covering the
  empty state, click-to-populate, the pressed/selected aria state, and
  keyboard activation.

### Key decisions

1. **Store carries the full Inspect payload** rather than just `{kind, id}` +
   a registry lookup. Rationale: the panel stays a pure renderer with no
   coupling to data modules, and any future "selectable thing" only has to
   know how to publish its own properties/tokens/used-in. Cheap to refactor
   later if the registry pattern ever becomes useful.
2. **`<div role="button">` instead of `<button>`** around `ExperienceCard`.
   `ExperienceCard` already wraps its content in `<article>` and a real
   `<button>` cannot contain `<article>` (invalid HTML). The div+role+tabIndex
   pattern is the standard WAI-ARIA escape hatch when semantics conflict.
   See override block in `biome.json`.
3. **`SelectableExperienceCard` as a separate wrapper** (not a `selectable`
   prop on `ExperienceCard`). Keeps the underlying card a pure server
   component, still usable from Storybook and any non-inspect doc context
   without bringing the nanostore into its bundle.
4. **`data-hydrated` marker** set inside `useEffect`. Without it,
   mobile-safari clicked before `client:idle` had mounted the React
   handlers, and 3 of 4 tests flaked. Same pattern as #4 ThemeToggle and #5
   LangToggle.
5. **`client:visible` on `InspectPanel` (not `client:load` or
   `client:only`)**. The panel is SSR'd in its empty state so there's no
   layout shift when the JS arrives — matches the AC "server-rendered with
   visible initial state (NOT client:only)". `client:visible` is enough
   because the panel is in the right column, always above the fold on
   desktop.

### Difficulties

- **Biome a11y/useSemanticElements conflict on `<div role="button">`**.
  Tried `// biome-ignore` first but the JSX attribute line attribution made
  Biome report "Suppression comment has no effect". Resolved with a
  file-level override block in `biome.json` scoped to the single file.
- **Mobile-safari hydration race on `client:idle`**. First Playwright run
  showed 40 passed / 3 failed (mobile-safari only). Fixed with a
  `data-hydrated` marker and a `selectableCard()` helper that awaits
  `data-hydrated="true"` before any click/keyboard interaction. After the
  fix: 43 passed / 1 skipped on both projects.
- **`pnpm preview` serves stale `dist/`**. Caught on the first re-run: even
  with the `data-hydrated` code in place, tests still failed because
  Playwright's webServer command is `pnpm preview` (not `build && preview`).
  Re-ran `pnpm build` before `pnpm test` and everything went green.

### Changements

1. **`stores/selected-item.ts` — nouveau helper `setSelection(next)`.**
   Encapsule `document.startViewTransition(() => flushSync(() => selectedItem.set(next)))`
   avec fallback SSR-safe et browser-support-safe. Pourquoi `flushSync` :
   `useStore` (donc `useSyncExternalStore`) déclenche un re-render React
   *après* l'event handler ; sans `flushSync`, la mutation passe en dehors
   du callback de `startViewTransition`, le browser snapshote le même DOM
   avant/après, et le morph ne joue pas. `flushSync` force le commit
   pendant le callback → snapshot diff réel → morph fluide.

2. **`SelectableExperienceCard.tsx` — utilise `setSelection()`.**
   Le `selectedItem.set(...)` direct est remplacé par `setSelection(...)`.
   `usedIn` href passe de `/patterns/timeline` (404 garanti) à `#` en
   attendant que le ticket Pattern Timeline atterrisse. Note inline dans
   le code pour signaler le swap futur.

3. **`InspectPanel.tsx` — `<aside>` → `<div>`.**
   Le `<aside class="app-inspect">` parent dans `DocLayout` porte déjà le
   landmark accessible ; pas besoin d'imbriquer un second `<aside>`.
