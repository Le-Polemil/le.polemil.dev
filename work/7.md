### Key decisions

- **Composants en React `.tsx` plutôt qu'`.astro`** : permet de les story-fier directement dans Storybook sans wrapper. Astro SSR rend très bien les composants React stateless (zéro JS shipped si pas de `client:*`). Pattern aligné avec Swatch (#6) et la stratégie Storybook (#27).
- **`Badge` est une primitive autonome** (pas inliné dans ExperienceCard, comme demandé par l'AC). Aussi extensible pour les autres variants status. Le bundle final reste minuscule (~20 lignes de markup et un CSS partagé).
- **`Tag` reste interne à ExperienceCard** : très spécifique à ce composant ; pas de gain à l'extraire en primitive tant qu'aucun autre composant ne l'utilise (YAGNI). À promouvoir si #13 (SkillCard) en a besoin.
- **`Avatar` reste interne aussi** : la lettre + couleur d'accent sont des conventions d'ExperienceCard ; ailleurs (sidebar, mentions) on aurait probablement des images, pas des initials → primitive séparée plus tard.
- **Timeline axis en CSS pur** (pseudo-elements `::before` line + `::after` dot) plutôt que l'image SVG du Figma. Plus léger, theme-aware, et le dot suit `--accent-timeline` automatiquement.
- **Variant `default` trim le stack à 3 + `+N`** ; `expanded` montre tout. `maxStackInline` est exposé en prop pour ajuster si besoin.
- **Compact n'a PAS de Badge `current`** dans le Figma — la spec privilégie la densité. J'ai respecté le design ; les tests assertent l'absence.
- **`colors.stories.tsx` renommé `_colors.stories.tsx`** : Astro émettait un WARN à chaque type-check (`Unsupported file type in pages directory`). Le préfixe `_` est la convention Astro pour ignorer un fichier dans le routing. À tracker : tous les futurs `*.stories.tsx` co-localisés dans `src/pages/` doivent avoir le préfixe `_`. **Suivi #6** documenté dans la review.

### 🟡 Important (non bloquant)

- **Badge utilise `inline-style` pour les variants** (objet `VARIANT_STYLES`) alors que `data-variant` est exposé sur le markup. Pattern incohérent avec ExperienceCard qui utilise `data-variant` + sélecteurs CSS. Conséquence : duplication entre TSX (couleurs) et CSS (layout). Migration vers CSS-only (`.badge[data-variant='success'] { background: …; color: …; }`) serait plus propre. **Pas bloquant** — le composant marche, le SSR/hydration n'a pas de mismatch (les inline styles sont stables), et c'est un refactor 5 minutes pour plus tard.

- **Padding `14px` hardcodé** dans default variant (et `pb 16/pt 12/px 14` dans timeline body) — Figma le veut ainsi, mais l'AC dit "spacings bindés aux tokens CSS". Strictement parlant, 14 n'est pas dans l'échelle `--space-*`. Options : (a) accepter (Figma = source de vérité), (b) ajouter `--space-3_5: 14px` au scale. J'accepte (a) ; on peut introduire `--space-3_5` quand un 2e composant le réclame.

### 🟢 Nits

- **`font-size: 10px` hardcoded** dans Badge.css et Tag CSS → pourrait être `var(--text-2xs)` (qui vaut 10px). Cohérence avec le reste du codebase.
- **`aria-label="… chez {company}"`** en français → même pattern hardcoded FR qu'avant (`Copié`, `Langue`). À tracker dans la migration i18n future.
- **`Tag` accepte `ReactNode` mais reçoit toujours string ou `+{number}`** → over-typed. Détail.
- **Avatar `size={20 | 28 | 32}`** typé en union littérale → cool ; les 3 tailles sont les seules autorisées.
