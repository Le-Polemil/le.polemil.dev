# 27 — chore(infra): Storybook for tokens / primitives / components / patterns visual verification

## 2026-05-12 — Initial development

### Summary
Storybook 10.3.6 installé avec le framework `@storybook/react-vite` et l'addon `@storybook/addon-themes`. Décorateurs custom qui pilotent `<html data-theme>` (light/dark) et `<body data-page>` (per-page accent) via la toolbar — match exact du contrat runtime. Stories rétroactives pour les tokens, ThemeToggle et LangToggle. CI : nouveau job `Storybook build` en `continue-on-error: true` pour ne pas bloquer pendant la rampe initiale.

### Key decisions

- **Framework : `@storybook/react-vite` plutôt que `@storybook/astro`** : SB10 ne fournit plus de framework Astro stable ; les composants critiques à story-fier sont les primitives React (`.tsx`) ; les `.astro` (Header, DocLayout, pages stub) sont essentiellement des assemblages SSR de ces primitives + markup statique — pas besoin de Storybook pour eux à ce stade. Le ticket mentionne `Header (variantes desktop/tablet/mobile)` et `DocLayout` comme cibles, mais ces stories nécessiteraient des wrappers React qui dupliqueraient le markup `.astro` — overhead non justifié pour le MVP. **Documenté comme follow-up** quand un usage clair émergera.
- **Addons : core uniquement + `@storybook/addon-themes`** : `@storybook/addon-essentials` est déprécié en SB10 (les essentials sont folded dans le core). Donc on n'installe que `storybook` + `@storybook/react-vite` + `@storybook/addon-themes`. 3 deps au lieu de 5+.
- **Décorateur custom plutôt que `withThemeByDataAttribute` de `addon-themes`** : on a besoin de driver DEUX attributs (`html[data-theme]` + `body[data-page]`) en même temps, avec deux globals indépendants. Le decorator unifié est plus propre.
- **Tokens story = React + CSS vars** : pas une story `.astro` (Storybook ne sait pas le faire), c'est un `TokensCatalog` React qui rend `<div style={{background: 'var(--bg-canvas)'}} />` etc. Les valeurs ne sont pas dupliquées, elles proviennent du `global.css` chargé via `.storybook/preview.tsx`. Switcher theme/page dans la toolbar reflète ce que la page réelle ferait.
- **`storybook-static/` ignoré partout** : ajouté à `.gitignore`, `biome.json` `files.ignore`, et `tsconfig.json` `exclude`. Sans ça, `astro check` crashait avec Abort trap en essayant de type-checker les bundles Storybook minifiés (~2 MB chacun).
- **CI job `continue-on-error: true`** : on durcira plus tard. Pour l'instant, mieux vaut signaler que casser CI le jour où on doit livrer une page critique.

### Difficulties

- **`@storybook/addon-essentials` 8.6.14 vs storybook 10.3.6** : peer dep mismatch silent — toutes les addons essentials veulent `storybook@^8.6.14` mais on installe la 10.3.6. Résolu en virant `addon-essentials` (folded dans core depuis SB9).
- **`astro check` crash sur `storybook-static/`** : Abort trap node, pas un message TS clair. Diagnostic via la taille des fichiers (vite-inject-mocker-entry.js > 100 KB minifié). Fix : exclude dans `tsconfig.json`. À retenir : tout dossier de build doit être exclu côté TS sinon `astro check` est exposé.
- **Pas de stories pour `.astro` files** : explicit follow-up gap (cf. Out of scope ci-dessous). Pas un blocker pour le ticket, mais à creuser quand on aura besoin de stories Header/DocLayout.

### Diff size
Difficile à chiffrer précisément (`pnpm-lock.yaml` génère plusieurs centaines de lignes de nouvelles deps Storybook). Code utile : `.storybook/main.ts` (~25 lignes), `.storybook/preview.tsx` (~100 lignes), 2 stories primitives (~25 lignes chacune), tokens story (~250 lignes), config files (3 lignes chacune). **~430 lignes de code utile** + lockfile généré. Single commit.
