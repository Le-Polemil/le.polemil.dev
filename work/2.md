# 2 — feat(foundations): polish tokens.css + wire @property --accent transitions

## 2026-05-10 — Initial development

### Summary
Câblage de la transition fluide de `--accent` entre pages (déjà déclaré `@property … syntax: '<color>'` dans `tokens.css`), garde `prefers-reduced-motion`, et `view-transition-name: root` sur `<html>` pour le crossfade entre routes Astro. Ajout d'une page stub `/components/experience` pour valider visuellement le morph d'accent entre deux pages (foundations → experience).

### Key decisions
- **Transition du `--accent` listée explicitement** dans la `transition: …` de `html, body`. Sans ça, l'@property est registered mais la valeur snap entre pages — il faut une déclaration de transition pour que la propriété custom soit animée comme `background-color`/`color`.
- **`view-transition-name: root` sur `<html>`** (et pas sur `<body>`) : c'est l'élément racine du document, on évite ainsi les conflits si plus tard d'autres view-transition-name sont posées sur des composants enfants.
- **`prefers-reduced-motion: reduce` → `transition: none`** sur `html, body`, plus `animation: none` sur les pseudo-éléments `::view-transition-{old,new}(root)` pour neutraliser aussi le crossfade Astro. C'est le critère d'acceptation explicite du ticket.
- **Page stub `experience.astro`** plutôt qu'une route fictive en runtime : route statique vraie, navigable, qui exercice la transition pour de vrai. Coût ~15 lignes, sera remplacée par le contenu réel via ticket #8.
