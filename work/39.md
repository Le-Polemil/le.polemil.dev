# 39 — fix(visual): bilingual swap, ExperiencePreview grid, missing left rail nav

## 2026-06-03 — Initial development

### Summary

Trois écarts visibles entre le live (`le.polemil.dev`) et Figma frame 5:5,
identifiés par audit DOM + screenshots. Tous corrigés :

1. Le swap CSS bilingue (FR/EN) ne masquait plus la langue inactive sur les
   pages qui posaient un `display:` sur un wrapper `[lang]`.
2. `/components/experience` rendait les 4 variants en colonne au lieu d'un
   grid 2×2 (Figma 52:2) dès que la main column < 856px.
3. Le rail gauche (`<aside class="app-sidebar">`) était vide — la nav
   structurée du Figma 5:5 n'existait nulle part.

### Files

- **`src/styles/base.css`** — règle du swap bilingue passée à
  `display: none !important`. Commentaire explique pourquoi (`!important`
  est légitime : Astro émet le CSS scoped *après* `base.css`, les deux
  sélecteurs ont la même spécificité (0,1,0), l'ordre source fait gagner
  le scoped — donc tout `display:` sur un `[lang]` wrapper invalidait le
  swap).
- **`src/patterns/ExperiencePreview.astro`** — remplacé `flex-wrap: wrap`
  + deux rows manuels par `display: grid; grid-template-columns:
  repeat(auto-fit, minmax(280px, 1fr))`. Naturellement 2×2 au desktop,
  fallback gracieux 1×N en plus étroit, pas d'overflow.
- **`src/components/cv/ExperienceCard.css`** — `.experience-card` passe de
  `inline-size: 420px` (rigide) à `inline-size: 100%; max-inline-size:
  420px` (fluide jusqu'à 420 max). Cap Figma conservé, mais la carte
  rétrécit dans une cellule de grid plus étroite.
- **`src/data/nav.ts`** (nouveau) — structure de la nav du rail gauche :
  3 sections (`Composants` / `Foundations` / `Patterns`), chacune avec un
  eyebrow FR/EN + items. Champs `href` (lien actif) ou `disabled: true`
  (placeholder muté pour les pages pas encore livrées). Helper
  `activeNavItem(pathname)` pour résoudre l'état actif.
- **`src/components/system/AppNav.astro`** (nouveau) — landmark
  `<nav aria-label="Navigation principale">`, eyebrows en `<h2>`, items en
  `<ul role="list">`. Chaque label rendu en double (`<span lang="fr">` +
  `<span lang="en">`) pour s'aligner sur le pattern bilingue déjà en place.
  Active state via `data-active="true"` + `aria-current="page"`.
- **`src/layouts/DocLayout.astro`** — `AppNav` est désormais le fallback
  par défaut du slot `sidebar` (même pattern que `InspectPanel` pour le
  slot `inspect` depuis #9).
- **`tests/playwright/visual-fixes-39.spec.ts`** (nouveau) — 3 tests
  couvrant les 3 corrections. Le test du grid 2×2 et celui de la nav sont
  skipped sur mobile-safari (viewport < 768 → sidebar `display:none` par
  design, grid 1×N attendu).

### Décisions

1. **`display: none !important` sur la règle du swap** plutôt que
   monter le sélecteur en spécificité ou passer par un `@layer`. C'est
   un "switch off entire branch" intent — pas un override de layout
   local — et le `!important` est confiné à une règle globale du framework
   bilingue. Commenté dans le code pour le futur lecteur.
2. **Grid `auto-fit minmax(280px, 1fr)`** plutôt que `flex: 1 1 300px`.
   Le grid garantit le 2×2 quand l'espace permet (≥ 580px effectif) et
   fallback proprement à 1×N sans laisser des cartes traîner au milieu
   d'une ligne. Plus robuste aux changements futurs de breakpoint.
3. **Cartes fluides via `max-inline-size`** plutôt que `inline-size`
   rigide. Conserve le cap Figma 420px mais autorise le rétrécissement
   dans la cellule de grid → pas d'overflow horizontal.
4. **Nav data-driven (`src/data/nav.ts`)** plutôt que dur dans
   `AppNav.astro`. Permet d'éditer la structure sans toucher au markup,
   et de raccrocher facilement les futures pages (foundations/typography,
   patterns/timeline, components/project, ...) en flippant `disabled:
   false` + ajout d'un `href`. Pas tiré du BO pour l'instant — le BO ne
   structure pas la nav du design system, c'est un truc propre à ce site.
5. **Bilingue de la nav par double rendu `lang=` + CSS swap** plutôt
   qu'un toggle React. Aligné sur le pattern déjà en place pour le
   reste, pas d'island nécessaire.

### Décisions saines (à garder)
- **`!important` sur la règle du swap** — confiné à un cas "switch off entire branch", commenté précisément avec la raison (Astro scoped CSS post-base, equal specificity). Justifié.
- **Card fluide `max-inline-size: 420px`** — conserve le cap Figma sans rigide. Robuste aux changements de breakpoint.

- **Nav data-driven via `src/data/nav.ts`** — `disabled: true` à flipper plus tard. Permet d'éditer la structure sans toucher au markup.

- **Active state du wrapper résolu via `Astro.url.pathname`** — propre côté SSG.

### 🟢 Nits non bloquants
1. **`aria-disabled="true"` sur un `<span>`** est largement cosmétique : les `<span>` ne sont pas focusables nativement, donc l'AT n'annonce pas "disabled". Si tu veux que les screen readers signalent "à venir / coming soon" sur ces items, ajouter un `aria-label="<X> - à venir"` ou un `<span class="sr-only">` à venir. Sinon visuellement OK.
2. **`!important` précédent** — la règle est bien commentée, mais à terme une approche `@layer` (genre `@layer i18n { ... }` plus prioritaire que le scoped) serait plus propre et éviterait le mot magique. Follow-up.
3. **Indicateur visuel des items disabled** — actuellement juste `color: var(--fg-tertiary)` + `cursor: not-allowed`. Le Figma 5:5 ne semble pas afficher d'indicateur explicite (juste muted), donc OK pour cette itération. À revoir si les utilisateurs cliquent les items et se demandent pourquoi rien ne se passe.
4. **Test du grid 2×2 utilise des Y pixels** (`Math.round(rect.top)`) — fragile au gap exact mais le gap actuel (110px) donne deux bands bien distincts. À reconsidérer si on changeait le gap à < 10px.
