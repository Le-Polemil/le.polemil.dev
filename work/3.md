# 3 — feat(system): complete DocLayout.astro — 3-column grid + responsive shell

## 2026-05-12 — Initial development

### Summary
Réécriture du body de `DocLayout.astro` pour devenir la coquille 3-colonnes du design system, avec :
- une `.app-shell` en CSS Grid (sidebar 220 / center 1fr / inspect 280) sur desktop ≥ 1024px,
- une **bascule via `body[data-inspect-open='true']`** pour le toggle Inspect en tablet 768-1023px (CSS-only — le bouton du Header arrive en #4),
- une mise en page mobile (< 768px) avec sidebar masquée (drawer = #10) et Inspect en peek bas fixe,
- 4 slots nommés exposés : `header`, `sidebar`, default (center), `inspect`,
- garde `prefers-reduced-motion` pour la transition slide-in du panneau Inspect.

### Key decisions
- **CSS-only toggle pour le tablet Inspect** : `body[data-inspect-open='true'] .app-inspect { transform: translateX(0); }`. #3 ne fournit aucun bouton — le ticket #4 (Header + theme toggle) ajoutera le JS qui flippe l'attribut. Cette séparation garde la couche layout sans dépendance JS et donne à #4 un point d'extension propre.
- **Mobile : Inspect en peek statique, pas en bottom sheet draggable** : la version draggable (geste swipe-up pour expand) appartient au ticket #10 (mobile shell). Pour #3, un panneau fixe en bas (hauteur `--size-control-lg`, overflow hidden) suffit à montrer qu'il existe et où il vit.
- **Sidebar masquée mobile** (`.app-sidebar { display: none }`) plutôt qu'off-grid avec transform : la spec déléguait explicitement le drawer à #10. Pas de plumbing prématuré.
- **`.app-main` porte le `max-inline-size: var(--size-center-max)` + `margin-inline: auto`** : la limite à 720px du contenu central est désormais portée par le layout, pas par chaque page. Les pages stub (`index.astro`, `components/experience.astro`) ont été nettoyées de leur padding/max-width redondants.
- **Sticky header avec `z-index: 10`** : le panneau Inspect (tablet en overlay) est sous le header (`z-index: 9`) pour qu'on puisse cliquer un futur toggle du Header sans qu'il soit masqué par Inspect.
- **Pas de scroll trap sur `.app-shell`** : le scroll reste sur le document, le `position: sticky` du header marche relativement au viewport. C'est la convention simple : pas de container scrollable interne au MVP.
