# 30 — chore(infra): deploy Storybook to Coolify (sb.polemil.dev)

## 2026-05-12 — Initial development

### Summary
Ajout de l'infra de déploiement Storybook : `Dockerfile.storybook` (multi-stage build, même pattern que le `Dockerfile` du site principal mais qui build `storybook-static/`) + `nginx.storybook.conf` (SPA fallback `try_files $uri $uri/ /index.html` pour gérer le routing client-side de Storybook). Mise à jour de `docs/04-architecture.md` §8.3 avec la config Coolify attendue, et README qui pointe vers `https://sb.polemil.dev` pour la vérif visuelle hébergée.

La création de l'app Coolify elle-même (UI sur `coolify.polemil.dev`) se fait **après le merge de cette PR**, via Chrome MCP par l'opérateur. Le repo livre tout le code nécessaire ; Coolify pointe sur ce Dockerfile.storybook.

### Key decisions

- **`Dockerfile.storybook` séparé du `Dockerfile`** principal : on déploie deux apps Coolify indépendantes (site prod + Storybook), avec des cycles de build différents. Un seul Dockerfile multi-target aurait nécessité de passer un build-arg côté Coolify — moins lisible. Fichiers séparés = pattern explicite.
- **`nginx.storybook.conf` SPA fallback** : Storybook gère son propre routing côté client (URL `/?path=/story/...`). Sans `try_files ... /index.html`, refresh sur une route Storybook → 404. Différent du site Astro principal dont les routes sont des fichiers HTML statiques.
- **`X-Frame-Options: SAMEORIGIN`** (vs `DENY` sur le site principal) : Storybook utilise des iframes same-origin pour son preview pane (canvas). `DENY` casserait l'iframe. `SAMEORIGIN` autorise uniquement la même origine, donc safe.
- **Pas de modif du `Dockerfile` ni du `nginx.conf` existants** : zero risk pour le déploiement prod actuel. Le site principal reste inchangé.
- **Webhook GitHub Actions** : laissé en TODO côté PO (à configurer dans `.github/workflows/deploy.yml` qui n'existe pas encore). Pour l'instant, le rebuild Coolify peut être déclenché manuellement OU via le webhook Coolify (URL générée à la création de l'app). Quand le `deploy.yml` apparaîtra, ce sera trivial d'ajouter l'appel à 2 webhooks (prod + storybook).
