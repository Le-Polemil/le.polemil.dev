# 5 — feat(i18n): LangToggle + JSON-based runtime swap (FR canonical)

## 2026-05-12 — Initial development

### Summary
i18n FR + EN avec **même URL** + persistence `localStorage`. FR canonique pour SEO (rendu `<html data-lang="fr">` par défaut). Helper TS strict typed `t(key, lang)` dérivé du JSON FR (canonique) via `typeof + satisfies` ; EN doit matcher l'arbre, sinon type-check échoue au build. LangToggle React island (`client:idle`) qui consomme le nanostore `lang`, persiste localStorage, et flip `document.documentElement.dataset.lang`. Premier vrai test Playwright pour la persistence i18n.

### Key decisions

- **FR canonique via TypeScript** : `const fr = frCommon; const en = enCommon satisfies typeof fr;`. Si EN n'a pas exactement les mêmes clés que FR, `pnpm type-check` échoue. Pas de codegen, pas de schéma JSON ; juste TS qui fait son boulot.
- **`<fieldset>` + `<legend>` plutôt que `<div role="group">`** : Biome `a11y/useSemanticElements` l'exige. UA defaults de fieldset reset dans le CSS (`margin/padding: 0; min-inline-size: 0`). Legend visuellement caché via clip-rect (le `aria-label` aurait été ignoré par les screen readers sur fieldset).
- **`LANGS` exporté depuis `lib/i18n.ts`** plutôt que dupliqué dans LangToggle : single source of truth. Type `Lang` aussi.
- **Suppression de `Pill.astro` orphelin** : depuis #4, c'était le placeholder visuel statique. LangToggle.tsx prend le relais (markup et CSS volontairement alignés sur ce que Pill.astro proposait, donc continuité visuelle). Si plus tard on a besoin d'un Pill statique, on le recrée — l'architecture doc (cf. `docs/04-architecture.md`) prévoit déjà `Pill.tsx` comme primitive interactive.
- **Bundle estimation** : LangToggle.tsx (~50 LOC) + `@nanostores/react` (~1KB gz) + `nanostores` core (~1KB gz) + le composant lui-même ≈ **2.5KB gz total**, sous le budget 5KB.
- **`data-hydrated` marker** : même pattern qu'#4 ThemeToggle, set par `useEffect` au mount. Le test Playwright attend ce marqueur avant de cliquer pour éviter les races `client:idle`.

### Difficulties

- **Conflit avec Biome `useSemanticElements`** : impossible de garder `<div role="group">` malgré le `biome-ignore` (la directive avec commentaires intermédiaires n'est pas appliquée). Migration vers `<fieldset>` + `<legend>` faite proprement.
- **Test sélecteur stale après le switch `<div>` → `<fieldset>`** : 1re run timeoutait sur `[role="group"][aria-label="Langue"]`. Corrigé : `fieldset.lang-toggle[data-hydrated="true"]`.
- **Préview server collé sur port 4321** (toujours, depuis #4). Workaround : `lsof -i :4321 -t | xargs kill` avant les runs, ou `CI=1 pnpm test`. À long terme, modifier `playwright.config.ts` (cf. follow-up dans #4).

### Out of scope — pour les tickets suivants
- **Contenu dual-render** : aucun composant n'a encore de `<span lang="fr">…</span><span lang="en">…</span>` à swapper via CSS. Le helper `t()` est prêt à être consommé par le 1er composant qui en a besoin (probablement #7 ExperienceCard ou #6 Foundations page).
- **JSON modules par section** : pour l'instant uniquement `common.json`. Les autres modules listés dans le ticket (`experiences.json`, `projects.json`, etc.) seront créés au moment où le contenu correspondant existe. Architecture prête (`src/i18n/<lang>/<section>.json`).
- **LangToggle Figma alignment** : le ticket ne référence pas de frame Figma précise pour la Pill (juste `14:20`). Le visuel actuel reprend les tokens (radius-full, border subtle, mono uppercase) mais n'a **pas** été comparé pixel-by-pixel à Figma. À traiter une fois Storybook (#27) en place pour la verif visuelle.
