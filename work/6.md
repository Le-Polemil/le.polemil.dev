### Key decisions

- **Foreground en `text-sample` plutôt que swatches de couleur** : la Figma rend les fg/* sous forme d'une colonne étroite 21px qui contient "Aa" coloré par le token. Sémantiquement plus juste qu'un bloc de couleur — on veut vérifier la lisibilité du texte, pas la teinte pure. Implémenté via un kind discriminé sur `Swatch.tsx`.
- **`color-tokens.ts` data module** : évite la duplication entre page Astro et story Storybook. Si on change un hex affiché, on le change à un seul endroit. Les hex restent purement informatifs — le rendu utilise toujours `var(--token)`, donc light↔dark fonctionne automatiquement.
- **Feedback "Copié" overlay inline plutôt qu'un Toast global** : Toast global aurait nécessité un store partagé entre îlots React + un composant TopLayer. Le simple overlay per-swatch est suffisant pour le besoin du ticket et garde le composant Swatch autonome.
- **`client:idle` cohérent avec ThemeToggle / LangToggle** : le marqueur `data-copied` est posé par `useState` (pas dans un useEffect), donc pas besoin du pattern `data-hydrated` pour synchroniser les tests. Le hydration-lag n'affecte pas le test (Playwright auto-attend la visibilité du bouton).
- **Test webkit skip volontaire** : `navigator.clipboard.writeText` n'est pas exposé en WebKit headless Playwright. Le composant marche sur Safari réel ; c'est un test environment gap. Documenté inline.

### Difficulties

- **`data-page` est sur `<body>`, pas `<html>`** (consommé par les CSS `body[data-page='…'] { --accent: … }`). Mon 1er test ciblait `html` → fail. Corrigé.
- **WebKit clipboard-write permission inconnue** : `context.grantPermissions(['clipboard-write'])` rejette en webkit. Resserré le grant à chromium uniquement + skip clipboard tests sur webkit.
- **Playwright browsers re-téléchargés** : le `~/Library/Caches/ms-playwright/webkit-2272` était stale après un upgrade Playwright. `pnpm exec playwright install chromium webkit` a corrigé.
