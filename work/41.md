### Décisions

1. **Notation tag conservée** sur les items CV (`<Experience />` → `<Experiences />`). Le user a précisé que le style "tag" fait partie de l'identité visuelle du design system nav — on garde donc les angle brackets, on pluralise simplement le nom. Section eyebrow reste "Composants" pour la même raison.
2. **Items pluriels où c'est sémantique** : Experiences, Projects, Skills. Contact reste singulier (ce n'est pas une page-liste). Les sections Foundations / Patterns inchangées.
3. **Nanostore + React island TemplateOptions** plutôt qu'un store local au component. Les options doivent être partagées avec ExperienceList qui est un autre island dans une autre colonne du layout. Nanostore + `useStore` est la seule façon propre de connecter deux islands sans serialization Astro.
4. **Accent override via CSS var sur le wrapper** (`style={{ '--accent': 'var(--accent-xxx)' }}`) — les composants downstream consomment déjà `var(--accent)`, donc la cascade fait le boulot. Aucune modification de l'ExperienceCard nécessaire.
5. **`data-show-stack="false"` + CSS rule** plutôt que prop `showStack` sur ExperienceCard. Moins invasif (pas de touch sur l'API du component), suffisant pour ce besoin (cacher = `display: none`).
6. **`document.startViewTransition` pour l'expand** plutôt qu'une lib d'animation. Native, progressive enhancement, et chaque card a un `view-transition-name: experience-card-N` pour que le browser morph individuellement entre les états collapsed/expanded. Le 1er card reste en place, les 2-5 apparaissent depuis leur position finale.
7. **`/components/experience` reste accessible** (Code/Props tabs intacts) — seulement unlinked de la sidenav. Pas de breakage des specs `#11` (dev-audit).
8. **Pill style strict au cahier des charges** : `border-radius: 9999px`, accent color, hover translateY + accent shadow. Bilingue via twin `<span lang>` (pattern existant).
