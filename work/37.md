### Décisions clés

1. **Snapshots JSON commités** plutôt que fetch au build. Garde le build
   reproductible offline ; le BO peut être indisponible sans casser la
   CI. Re-snapshot manuel via `pnpm fetch-content` quand le contenu
   bouge — pas de cron pour l'instant.
2. **Stack par expérience curé localement.** Le BO ne stocke pas un
   `stack[]` typé sur `Job`. Plutôt que d'inférer depuis les projets,
   j'ai posé une table `STACK_BY_KEY` dans `experiences.ts`. Cinq
   entrées, low-maintenance, et reflète ce qui est mis en avant
   visuellement (≠ liste exhaustive). À reconsidérer si on rajoute la
   relation côté BO.
3. **Descriptions narratives inline** (`DESCRIPTIONS.fr.elao = "…"`)
   plutôt que dans `i18n/*.json`. Garde le module `Experience`
   self-contained (l'i18n JSON reste du micro-copy d'UI). Si on doit
   ajouter une 3ème langue ou si la prose commence à diverger entre
   surfaces, on pousse dans i18n.
4. **Bilingue via blocs jumeaux + CSS swap**, pas Astro i18n routing.
   Aligné sur le pattern existant (`#lang-toggle` + `[data-lang]`
   selector dans `base.css`). Pas de nouvelle config Astro à introduire.
5. **Rebase sur `feat/11-quality-gates`** (vs `main`) parce que mon home
   change le h1 → invalidait les persona specs de #11. Décrit en haut
   de doc.

### Difficultés

- **TypeScript inférait `id: number`** sur `SkillSubCategory` à partir
  du JSON, mais Strapi renvoie les IDs comme strings ("37086"). Aligné
  le type sur `string`.
- **Tests existants cassaient** sur le contenu du nouveau fixture
  (`Lead front-end` → `Lead développeur front-end`, etc.). 7 assertions
  réécrites dans `experience-card.spec.ts` + `inspect-panel.spec.ts`.
- **Strict mode locator** sur l'expanded variant : `getByText(/Elao/)`
  matchait 2 éléments (role-line + description). Switch vers
  `.experience-card-description` + `toContainText(/J'intègre Elao/)`.
