# 37 — feat(content): seed data from polemil.dev BO

## 2026-05-26 — Initial development

### Summary

Aspire le contenu du Strapi BO existant (`https://bo2.polemil.dev/graphql`)
dans des snapshots JSON commités sous `src/content/`, expose des modules
data TypeScript locale-aware (`experiences`, `projects`, `skills`,

CV, en FR par défaut et en EN via le toggle de langue (rendu bilingue +
CSS swap, pattern déjà en place dans le repo).

### Décisions clés

1. **Snapshots JSON commités** plutôt que fetch au build. Garde le build
   reproductible offline ; le BO peut être indisponible sans casser la
   CI. Re-snapshot manuel via `pnpm fetch-content` quand le contenu
   bouge — pas de cron pour l'instant.
2. **Stack par expérience curé localement.** Le BO ne stocke pas un
   `stack[]` typé sur `Job`. Plutôt que d'inférer depuis les projets,
   j'ai posé une table `STACK_BY_KEY` dans `experiences.ts`. Cinq
   entrées, low-maintenance, et reflète ce qui est mis en avant
   visuellement (≠ liste exhaustive). À reconsidérer si on rajoute la
   relation côté BO.
3. **Descriptions narratives inline** (`DESCRIPTIONS.fr.elao = "…"`)
   plutôt que dans `i18n/*.json`. Garde le module `Experience`
   self-contained (l'i18n JSON reste du micro-copy d'UI). Si on doit
   ajouter une 3ème langue ou si la prose commence à diverger entre
   surfaces, on pousse dans i18n.
4. **Bilingue via blocs jumeaux + CSS swap**, pas Astro i18n routing.
   Aligné sur le pattern existant (`#lang-toggle` + `[data-lang]`
   selector dans `base.css`). Pas de nouvelle config Astro à introduire.
5. **Rebase sur `feat/11-quality-gates`** (vs `main`) parce que mon home
   change le h1 → invalidait les persona specs de #11. Décrit en haut
   de doc.

### Décisions saines (à garder)
- **Snapshots JSON commités** : build reproductible offline, BO peut être en maintenance sans casser la CI. Excellent pour la fiabilité.
- **Stack curé localement** dans `STACK_BY_KEY` : le BO n'expose pas le champ, ça reste 5 entrées low-maintenance. Bien commenté.
- **Descriptions inline** dans `experiences.ts` : trade-off explicite (self-contained module vs i18n centralisé), bien argumenté.
- **PR base = feat/11-quality-gates** : prévient un breakage des persona specs de #11. Bonne pratique de signaler la dépendance en haut de PR.
- **Recruiter timing scopé à la 2ème nav** : fix élégant du flake risk précédemment flaggé.
- **`as ReadonlyArray<RawJob>` cast scope minimal** : sound enough — le cast est confiné aux modules data, le type interne `RawJob` reste strict.

### 🟢 Nits non bloquants

1. **`STACK_BY_KEY` drift risk** : si une nouvelle entrée `Job` atterrit dans le BO avec une key inconnue, `stack` sera `[]` silencieusement. Pas grave mais on perd la check côté CI. Une assertion `console.warn` dans le script ou un test unitaire `EXPERIENCES.every(e => e.stack.length > 0)` couvrirait ça si on veut être paranoïaque.
2. **Type assertions sur les imports JSON** (`as { jobs: ReadonlyArray<RawJob> }`) : un module `src/content/types.d.ts` qui déclare le shape des JSON serait plus propre — on enlèverait les `as` et TS validerait au import. Refactor mineur, suite.
3. **`months[Number(ms) - 1]`** : avec `noUncheckedIndexedAccess`, le résultat est `string | undefined`. Si une date BO est malformée ("0" ou "13"), on rendrait `"undefined 2024"`. Edge case improbable (Strapi normalise les dates), mais une garde `?? ''` ou un check de range serait sain.
4. **Deux `<h1>` rendus sur la home** (un par lang block). HTML5 outline autorise, axe passe, mais c'est inhabituel — un futur lecteur d'écran qui traverse le DOM avant le CSS swap pourrait voir les deux. Probablement OK avec le `display: none` qui exclut du AOM, mais à valider en passe a11y dédiée.
5. **Le script `fetch-content` n'a pas de retry** sur erreur réseau. Un seul fetch raté = exit 1. Pas critique (manuel, on rerun à la main), mais 1-2 retries seraient gratuits.
